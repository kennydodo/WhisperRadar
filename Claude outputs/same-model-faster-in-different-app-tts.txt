First, what does an app actually do? The model file is a long list of numbers, called weights, that the model learned during training. The file can't run itself. Step one. Record what each app is doing now. Write down the model file name, its size in gigabytes, its number of bits, which is often called the quantization, the context length, how many layers are on the card, and the app's version. Fewer bits make the file smaller, and can change the answers slightly.

Step two. Make the two setups match. Name, size and bit depth are useful clues. Loading exactly the same file in both apps is stronger evidence. Then set the same context length in both.

Step three. Check where each one ran. Look at how many layers are on the card, and how much V-RAM is in use. If anything is in normal memory, fix that first.

Step four. Warm up both apps, then rerun the same prompt in each. A model does two jobs on every request. First it reads your prompt. Then it writes the reply one token at a time. So write down three numbers separately: the time until the first token appears, the speed of the reply, and the total response time. A long document with a short answer can look slow in total time even when the reply speed is fine. If loading time matters to you, measure that separately too.

Step five. Change one setting at a time, rerun the same prompt, and write down what happened. If you change three things at once, you won't know which one mattered.
